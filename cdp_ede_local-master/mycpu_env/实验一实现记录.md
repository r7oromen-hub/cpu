## 3. 文件结构与修改内容

### 3.1 顶层与总线

- `myCPU/mycpu_top.v`
  - 将单周期组合数据通路替换为五个流水级实例。
  - 增加两个 RAM 片选端口。
  - 将两个 RAM 写使能端口改为 4 位。
  - 连接 `br_bus`、四组级间总线和 `ws_to_rf_bus`。
- `myCPU/mycpu_head.v`
  - 新增总线宽度宏和 include guard。
  - 总线宽度如下：
    - `BR_BUS_WD = 33`
    - `FS_TO_DS_BUS_WD = 64`
    - `DS_TO_ES_BUS_WD = 148`
    - `ES_TO_MS_BUS_WD = 71`
    - `MS_TO_WS_BUS_WD = 70`
    - `WS_TO_RF_BUS_WD = 38`

### 3.2 五级流水模块

- `myCPU/if_stage.v`
  - 维护 `fs_pc` 和 `fs_valid`。
  - 根据 ID 级的 `br_bus` 选择顺序 PC 或跳转目标。
  - 在访问同步指令 RAM 时用 `nextpc` 发起请求，使下一周期返回的指令与更新后的 `fs_pc` 对齐。
- `myCPU/id_stage.v`
  - 完成 20 条基础指令的译码、立即数生成和寄存器读取。
  - 在 ID 级判断分支并生成 `br_bus`。
  - 将后续流水级需要的控制信号、操作数和 PC 打包到 `ds_to_es_bus`。
  - 从 WB 级接收 `ws_to_rf_bus` 并写寄存器堆。
- `myCPU/exe_stage.v`
  - 执行 ALU 运算。
  - 为 `ld.w/st.w` 产生数据 RAM 地址和写数据。
  - 用 `es_valid` 限定 RAM 片选和写使能，避免无效指令产生副作用。
- `myCPU/mem_stage.v`
  - 将同步数据 RAM 的读数据与对应 load 指令对齐。
  - 在 ALU 结果和 RAM 读数据之间选择最终写回结果。
- `myCPU/wb_stage.v`
  - 产生寄存器堆写回总线。
  - 调试接口统一来自 WB 级。
  - 用 `ws_valid` 限定写回使能。

### 3.3 基础模块修复

- `myCPU/alu.v`
  - 删除 `or_result` 对 `alu_result` 的组合反馈，消除组合环路。
  - 修正移位指令的操作数方向，应为 `rj` 按立即数移位。
  - 修正算术右移结果最高位丢失的问题。
  - 使用明确的有符号/无符号比较实现 `slt/sltu`。
- `myCPU/regfile.v`
  - 禁止向 0 号寄存器写入，保持架构语义。

### 3.4 测试环境改进

- `soc_verify/soc_bram/testbench/mycpu_tb.v`
  - 原测试台无条件执行 `$dumpvars`，会把两块大 RAM 全部写入 VCD，仿真在时间 0 附近长时间停顿。
  - 改为只有传入 `+DUMP_WAVE` 时才生成波形，并且仅导出 CPU 层次。
- `soc_verify/soc_bram/testbench/Makefile`
  - 增加源文件依赖，修改 Verilog 后会自动重新编译。
  - 使用 `-g2012 -Wall` 编译。
  - 增加 `wave` 目标；普通 `iverilog` 目标默认不写 VCD。

## 4. 流水控制设计

每一级均采用相同的握手形式：

```verilog
assign stage_allowin = !stage_valid ||
                       (stage_ready_go && next_stage_allowin);
assign stage_to_next_valid = stage_valid && stage_ready_go;
```

实验一中所有阶段均能在一个周期完成，因此各级 `ready_go` 固定为 1。复位时清空所有 `valid`，只有有效指令才能执行 RAM 写和寄存器写等有副作用操作。

### 4.1 级间信息

- IF -> ID：指令、PC。
- ID -> EXE：访存/写回控制、目的寄存器、ALU 操作、两个 ALU 操作数、store 数据、PC。
- EXE -> MEM：load 标志、写回控制、目的寄存器、ALU 结果、PC。
- MEM -> WB：写回控制、目的寄存器、最终结果、PC。
- WB -> ID：寄存器写使能、写地址、写数据。

## 5. 实现中发现的问题

### 问题 1：提供的顶层接口与 `soc_bram` 不一致

现象：原 `mycpu_top.v` 缺少 RAM 片选信号，写使能只有 1 位，而 `soc_lite_top.v` 连接的是片选加 4 位字节写使能。

处理：按照指导书修改顶层端口；指令 RAM 禁止写，`st.w` 对数据 RAM 四个字节同时使能。

### 问题 2：原 ALU 存在组合环路

现象：原代码为 `or_result = alu_src1 | alu_src2 | alu_result`，而 `alu_result` 又依赖 `or_result`。

处理：将 OR 运算修正为 `alu_src1 | alu_src2`。

### 问题 3：原移位数据方向错误

现象：原代码使用立即数作为被移位数据，并使用寄存器值作为移位量；算术右移还遗漏结果最高位。

处理：统一改为 `alu_src1` 是被移位的 `rj`，`alu_src2[4:0]` 是移位量，并使用 `$signed(...) >>> ...` 完成算术右移。

### 问题 4：`bl` 没有写回 1 号寄存器

现象：原 `gr_we` 表达式错误地排除了 `bl`，导致链接地址不能写入 `$r1`。

处理：`bl` 保持寄存器写使能，并将目的寄存器选择为 1。

### 问题 5：调试写使能名称拼写不一致

现象：端口名是 `debug_wb_rf_we`，原代码却驱动了未声明的 `debug_wb_rf_wen`。

处理：调试信号全部在 WB 模块中产生，并使用声明一致的端口名。

### 问题 6：完整 VCD 导出严重拖慢仿真

现象：第一次运行生成约 61 MB VCD 后仍未进入测试；即使限制到 CPU 层次，完整回归仍持续写入数十 MB 波形。

处理：默认关闭 VCD；需要观察波形时使用 `make wave` 显式开启。

### 问题 7：`$readmemb` 报告初始化文件短于 RAM 深度

现象：Icarus 提示 `inst_ram.mif` 和 `data_ram.mif` 没有覆盖 RAM 声明的全部地址范围。

判断：测试镜像只保存实际使用的存储区，其余地址未初始化；这是课程镜像与 RAM 深度之间的正常差异，不影响本实验执行路径。20 个功能点和完整写回对拍均通过，因此未对测试镜像进行无意义补零。

## 6. 测试过程与结果

### 6.1 测试镜像

使用 `for_test_obj/ex1_obj` 中的：

- `inst_ram.mif`
- `data_ram.mif`
- `inst_ram.coe`

### 6.2 参考轨迹

```sh
make iverilog
```

生成的 `golden_trace.txt` 共 46,534 条有效写回记录，最后一条写回 PC 为 `0x1c000100`。

### 6.3 被测 CPU

在 `mycpu_env/soc_verify/soc_bram/testbench` 中执行：

```sh
make clean
make iverilog
```

结果：

- Verilog 编译成功，无端口、位宽、未声明信号或组合环路警告。
- 仅保留课程框架部分模块缺少显式 `timescale` 的非功能性警告。
- `$readmemb` 会提示镜像短于 RAM 总深度；未访问区域保持未初始化，不影响本测试。
- 20 个功能测试点全部显示 `PASS`。
- 写回 PC、目的寄存器号和写回数据逐条与 `golden_trace.txt` 一致。
- 最终输出：`----PASS!!!`。

需要波形时执行：

```sh
make wave
```
